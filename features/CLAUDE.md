# Agent Operating Protocol v2.0

> 设计原则：每一个 token 都必须直接参与推理。机制服务于任务，而非任务服务于机制。

---

## 0. 元规则：轻量旁路

在执行任何重型机制前，先判断任务复杂度：

- **轻量任务**（单文件修改、格式调整、变量重命名、简单问答）→ 跳过规划模式、错误记忆扫描、子代理分配，直接执行。
- **标准任务**（多文件修改、功能新增、Bug 修复）→ 启用规划 + 错误记忆扫描。
- **重型任务**（架构变更、跨模块重构、新系统设计）→ 启用全部机制，含子代理、验证循环、角色压缩。

判断标准：涉及 ≥3 个文件 或 包含设计决策 或 影响外部系统 → 至少为标准任务。

## 1. Think Before Coding

**Don't assume. Don't hide confusion. Surface tradeoffs.**

Before implementing:
- State your assumptions explicitly. If uncertain, ask.
- If multiple interpretations exist, present them — don't pick silently.
- If a simpler approach exists, say so. Push back when warranted.
- If something is unclear, stop. Name what's confusing. Ask.

---

## 2. 强制规划（标准任务及以上）

- 涉及 3 步以上或包含设计决策的任务，必须进入规划模式。
- 遇到问题不要强行推进，立即停止并重新规划。
- 验证阶段也使用规划模式。
- 开始前先写详细规范，减少歧义。

### 规划格式

```
## Plan
1. [Step] → verify: [check]
2. [Step] → verify: [check]
3. [Step] → verify: [check]
```

### 任务管理

- **先计划：** 在 `tasks/todo.md` 中写入可勾选的计划。
- **确认计划：** 实现前征求用户确认。
- **进度管理：** 及时勾选已完成项。

---

## 3. Goal-Driven Execution

**Define success criteria. Loop until verified.**

Transform tasks into verifiable goals:

| 模糊指令 | 可验证目标 |
|----------|-----------|
| "Add validation" | Write tests for invalid inputs, then make them pass |
| "Fix the bug" | Write a test that reproduces it, then make it pass |
| "Refactor X" | Ensure tests pass before and after |

Strong success criteria let you loop independently. Weak criteria ("make it work") require constant clarification.

---

## 4. 子代理使用（重型任务）

- 为保持主窗口整洁，积极使用子代理。
- 调研、探索、并行分析交给子代理处理。
- **1 个子代理 = 1 个任务**，禁止混合。
- 子代理返回结果时，主窗口仅保留结论与关键数据，丢弃过程。

---

## 5. 完成前验证

- 未经运行确认，不得视为任务完成。
- 自问："首席工程师会批准这个改动吗？"
- 执行：测试运行、日志确认、正确性证明。
- 若是权宜之计（Hack），标记 `@todo: replace_hack`，下次迭代根治。

---

## 6. 自主 Bug 修复

- 接到 Bug 报告后，立即检查日志、错误信息和失败的测试。
- 不要要求用户进行手把手的指示。
- 修复后必须补充回归测试。

---

## 7. 核心原则

- **简单第一：** 修改尽可能简单，影响范围最小。
- **根治问题：** 禁止临时补丁，必须解决根本原因。
- **关键修改时停下来思考：** "有没有更好的方法？"

---

## 8. Context Compaction 规则

> 压缩前提取上下文中的因果链、逻辑链、操作链、叙事链、时间链并完整保留，总占用不超过上下文比例的 15%。

### 8.1 触发机制（预测式压缩）

- **监控 token 增长速率**，预计 3 轮内超过 75% 时提前触发压缩（避免悬崖效应）。
- 弹性压缩带：75%–85% 为渐进压缩区间，非一次性截断。
- 保留最近 **5 轮**完整对话不压缩。
- 仅对超过 **10 轮**的对话进行压缩。

### 8.2 通用压缩规则

- ✅ 保留：代码变更记录、架构决策、错误信息与解决方案、关键约束
- ❌ 丢弃：调试尝试性命令输出、重复文件读取结果、成功测试的完整日志

### 8.3 语言专用规则

**TypeScript：**
- 保留：类型定义修改、接口变更、函数签名与返回类型变化
- 忽略：变量名重构、格式调整、import 顺序

**Python：**
- 保留：函数参数/返回值变化、装饰器与上下文管理器使用
- 忽略：导入语句顺序、docstring 格式微调

### 8.4 任务专用规则

| 任务类型 | 保留 | 忽略 |
|---------|------|------|
| API 开发 | API 端点设计、响应格式讨论 | 前端 UI 组件实现细节 |
| 调试 | 错误堆栈、日志分析、根因判断 | 成功的测试运行结果 |
| 重构 | 架构决策、代码迁移路径 | 中间尝试性重构步骤 |

### 8.5 关键信息标记（压缩时必须保留）

| 标记 | 含义 |
|------|------|
| `@important` | 核心业务逻辑讨论 |
| `@decision` | 架构决策记录 |
| `@warning` | 潜在风险和注意事项 |
| `@todo` | 待办事项列表 |
| `@false_positive` | 误报标记（用于错误记忆修正） |

### 8.6 压缩后状态恢复

**增量恢复原则：** 仅恢复变更部分，非全量重载。

**必须输出的恢复摘要：**
- 当前工作目录（显式声明）
- 已修改文件列表（仅变更部分）
- 未完成任务列表
- 已发现的问题和解决方案
- 错误记忆块（完整输出）

**恢复文件优先级：**
1. 主应用入口文件
2. 路由配置文件
3. 核心业务逻辑文件
4. 数据库模型文件
5. 测试配置文件

### 8.7 压缩禁止事项

- ❌ 不得删除错误信息
- ❌ 不得删除架构决策
- ❌ 不得删除待办事项
- ❌ 不得清空错误记忆块（除非用户明确要求）

## 9. Error Memory 系统

### 9.1 预算

- 错误记录固定占用上下文预算的 **10%**。
- 使用率超过 80% 时：合并同类错误，移除超过 10 轮未出现且置信度低的旧记录。

### 9.2 错误标识格式

| 错误类型 | 前缀 | 示例 |
|---------|------|------|
| TypeScript 类型错误 | `ERR_TS_` | `ERR_TS_MissingProperty` |
| Python 运行时异常 | `ERR_PY_` | `ERR_PY_KeyError` |
| 工具调用失败 | `ERR_TOOL_` | `ERR_TOOL_FileNotFound` |
| 逻辑/业务错误 | `ERR_LOGIC_` | `ERR_LOGIC_OffByOne` |

### 9.3 记录结构

```markdown
## Error Memory
- [标识] 发生: N次 (轮次: ...)  置信度: high/medium/low
  解决: 简要描述
  规避: 可执行的检查或代码模式
  有效期: YYYY-MM-DD（超期未复现则降级）
```

### 9.4 更新规则

- 每次压缩时扫描历史，识别错误信息。
- 标识不存在 → 新建（初始置信度 medium）。
- 已存在 → 增加计数，更新轮次，置信度升为 high。
- 同一标识发生 ≥2 次 → 增加 `#recurring` 标记。

### 9.5 防幻觉污染

- 用户标记 `@false_positive` 的错误 → 立即移除或降级为 low。
- 超过 **20 轮**未复现且置信度为 low 的记录 → 自动清除。
- 错误归因存疑时，标注 `置信度: low`，不触发主动规避。

### 9.6 主动规避协议（标准任务及以上）

生成代码或回答前执行：
1. 读取 `## Error Memory` 块。
2. 当前任务与已有错误场景相似时，输出：
   > ⚠️ 检测到历史错误 `[标识]`，规避建议：`[规避建议]`
3. 用户要求忽略 → 记录 `@decision: ignore_ERR_xxx`。
4. 轻量任务跳过此步骤。

## 10. Token 预算分配

| 组成部分 | 预算 | 说明 |
|----------|------|------|
| 系统提示词 | 10% | 固定 |
| 对话历史 | 50% | 压缩后 |
| 错误记忆 | 10% | 错误标识及规避建议 |
| 工具结果 | 20% | 文件读写、命令执行等 |
| 输出预留 | 10% | 当前回答生成 |

### 动态调整

| 条件 | 调整 |
|------|------|
| 利用率 > 80% | 工具结果降至 10%，错误记忆保持 10% |
| 利用率 < 50% | 输出预留增至 15%，错误记忆可降至 5%（若无近期错误） |
| 轻量任务 | 错误记忆预算释放给工具结果 |

## 11. 角色压缩标准

> 角色标准外部化为 `.agent-roles.yaml`，支持版本控制与团队共享。

**内置默认：**

| 角色 | 保留 | 忽略 |
|------|------|------|
| 开发人员 | 代码变更、技术实现、错误记忆 | 项目管理、沟通记录 |
| 测试人员 | 测试用例、缺陷记录（ERR_LOGIC 类） | 代码实现细节 |
| 产品经理 | 需求讨论、功能决策 | 技术实现、错误记忆 |

**自定义格式（`.agent-roles.yaml`）：**

```yaml
roles:
  backend_dev:
    retain: [code_changes, api_design, error_memory]
    discard: [ui_discussion, meeting_notes]
  data_engineer:
    retain: [pipeline_design, schema_changes, error_memory]
    discard: [frontend_code, styling]
```

## 12. Compact 指令模板

### 通用

```
/compact 总结对话，包括：
1. 已完成工作
2. 待完成任务
3. 关键决策（@decision）
4. 问题与解决方案（含错误记忆摘要）
5. 下一步计划
```

### 任务专用

```
/compact [API开发] 保留所有API端点设计和响应格式讨论，忽略前端UI细节
/compact [调试] 保留错误堆栈和日志分析，忽略成功测试结果
/compact [重构] 保留架构决策和迁移路径，忽略中间尝试步骤
```

### 恢复

```
/compact 压缩后增量恢复当前工作状态、错误记忆和变更文件
```

## 13. 故障排除

| 问题 | 解决方案 |
|------|----------|
| 压缩后丢失关键信息 | 增加 `@important` 标记；检查是否触发了悬崖效应 |
| 压缩频繁影响效率 | 检查是否误将轻量任务判为重型；提高弹性带下限 |
| 恢复状态不完整 | 确认增量恢复列表是否覆盖核心文件；显式输出错误记忆 |
| 错误标识过多/混乱 | 执行合并；清理 >20 轮未复现的 low 置信度记录 |
| 错误记忆误导（幻觉污染） | 用户标记 `@false_positive`；检查归因逻辑 |
| 机制本身成为负担 | 启用轻量旁路；审视该机制是否在当前任务中产生价值 |

---

## 14. 性能指标

| 指标 | 目标 |
|------|------|
| 压缩触发频率 | < 5 次/小时 |
| 信息丢失率 | < 5%（错误记忆 < 1%） |
| 恢复时间 | < 2 秒 |
| 重复错误率 | 相比无错误记忆降低 ≥ 50% |
| 轻量任务额外开销 | < 1 轮（旁路生效） |

---

## 15. 维护与演进

- **Error-Driven Update：** Agent 犯错后，追问"这条规则能否从代码/上下文读出？"若不能，补入对应模块；若能，检查为何未生效。
- **月度清理：** 审查 Error Memory 中 >20 轮未复现的记录；审查角色标准是否过时；清理 `@todo: replace_hack` 列表。
- **版本化：** 本协议标注版本号。每次重大修改记录 changelog，避免成为新的"过时注释"。
- **终极检验：** 删掉任何一行后，若 Agent 行为无变化，则该行是噪音，应删除。
